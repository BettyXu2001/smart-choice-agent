## 产品设计

左侧保留聊天及输入，快捷问题缩到输入区；右侧显示最新完整结果，历史卡片折叠为“查看当时推荐”，避免重复占满对话。会话 ID / Trace 放详情入口。

| 右侧区域 | 内容和操作 |
| --- | --- |
| 本次需求 | 显示目标；修改引导回对话，不另建目标编辑器。 |
| 当前条件 | 餐次、口味、健康目标默认展示；场景、菜系、便利性、心情按已有值或“添加条件”展开。编辑、清空、保存、取消。 |
| 待确认理解 | 模型理解及来源未知的旧值；确认、修改或移除。无内容时隐藏。 |
| 忌口与排除 | 已有可执行排除与待确认限制分开；编辑只提供已有可过滤选项。 |
| 当前推荐 | 主推荐、备选、理由和现有反馈；三餐按餐次分组，保留缺少匹配项提示。 |
| 还需补充 | 当前澄清问题，可聚焦字段或输入框。 |

不显示 agent 日志、置信度数字或原始权重。数据源折叠保留，切换后显式重取候选。

草稿与已保存状态分开，“保存并更新”一次提交。处理中标明更新中；成功替换，失败保留草稿和最后有效状态。待澄清、无候选、风险状态不展示过时推荐为当前结论。

## 状态设计和优先级

DecisionState 是权威；复用 domainState.slots，加入饮食范围字段元数据 domainState.dietFieldState，经 Pydantic 校验后存既有 JSON，无新增数据库表。

记录字段 source（明确对话、面板编辑、模型理解、历史未知）、confirmed、updatedRevision、显式清空标记；由服务端生成可信来源，客户端不能自行声称确认。

- patch 未出现字段不变，数组替换当前值，空数组清空；白名单校验字段、选项、类型和长度。
- 明确对话“改成、取消、不限”等走同一替换/删除能力；普通补充保留原合并语义，不全局重写 SlotBundle.merged_with。
- 当前原文能确定且无否定冲突的规则结果可标记已表达；模型独有结果标为待确认，不能仅信任模型声称用户已说过。
- 最新明确用户操作 > 旧确认值 > 无依据模型推断；明确新指令能改旧值。含糊冲突先保留并追问。
- 清空标记防止模型从历史恢复删除值。模型理解可作为标明来源的软偏好；未经确认不新增硬限制。
- 历史字段缺少来源时保留行为但标为待确认；确认相同值不必重算。
- slots 更新同步派生软约束，删除对应旧值并保留无关硬约束，避免下一轮旧条件复活。
- 任意食材过滤不在本轮范围。未支持的食材限制显示尚未验证，不宣称已满足；扩展食材模型需另行研究批准。

## API 和关键流程

饮食页面继续使用 DietApi / DietOrchestrator。增加薄的状态/编辑入口，复用现有阶段和 Presenter，避免同时经 GenericOrchestrator 写入饮食消息。

1. GET /api/v1/diet/sessions/{session_id}/state：校验 owner，返回当前 DecisionState 与聊天展示快照，空会话有明确空状态。
2. POST /api/v1/diet/sessions/{session_id}/commands：commandId、expectedRevision、严格类型 payload；首版 update_fields、confirm_fields、set_source，清空由空数组表达，返回 ChatResponse。
3. chat 新页面发送 expectedRevision；新增可选 requestId 供幂等重试，旧请求兼容。
4. 同决策内同 ID 同内容重试返回保存结果，不重复推进；同 ID 不同内容报错。轮次响应快照与消息、revision 一并保存在现有 JSON。

编辑链：加载并校验版本 → 验证 patch → 更新字段及派生条件 → 检查澄清、风险、三餐意图 → 复用统一阶段计算 → 保存状态/消息/事件/响应 → 同步两侧。

面板摘要不交给 LLM 再解析，不重置当前三餐意图。饮食层准备上下文并检查澄清，复用已有 run/recompute 和阶段方法，不复制候选排序或风险流程。确认同值只更新确认状态及版本。聊天记录加入明确摘要，如“已将餐次从晚餐改为午餐”。

## 事务、并发和恢复

- 当前饮食请求的 session、DecisionState、消息、编辑事件、响应快照为一个提交单元，复用条件 revision 更新。
- repository 增加可选不提交/flush 路径，默认行为兼容其他调用；失败 rollback，失败 Trace 独立记录，不提交半份业务状态。
- 前端按 userId 保存当前 sessionId，刷新从服务端恢复；不把浏览器缓存作为真值。
- 新会话清理面板、草稿、恢复指针；按 sessionId/revision 丢弃旧请求的 UI 回包。
- 新轮次保存展示快照；旧会话无历史快照时恢复文字和最新结果，不伪造历史卡片。
- 409 读取最新状态，保留草稿并提示重新提交；网络结果不明时用同一 ID 重试。
- 发送和编辑共用 pending 状态；不并发写入，保留输入草稿、焦点及主动滚动位置。

## 兼容性、风险和取舍

不增依赖或数据库结构迁移，旧 JSON 缺新字段时回退历史未知来源。明确纠正替代此前累加是预期行为修复，普通补充仍须回归。

事务是主要工程风险，修改限于本轮饮食链路，通用 API 必须回归。不为了改面板顺带重构全库。

无候选不自动放宽硬约束；必要字段清空后重新澄清；三餐编辑保留 composition；健康风险不能被面板操作绕过。非必要字段清空不应反复追问。

不新增流式传输、完整会话列表、评分权重面板或自动食材推理。
