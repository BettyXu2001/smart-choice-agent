# 首页价值定位与 Offer 旗舰示例 Plan

## 目标和成功标准

让用户在第一屏理解 Choice Agent 的差异化价值，并通过 Offer 旗舰案例快速看懂它最适合处理的复杂选择。

成功标准：

- 保留“把选择题想清楚”。
- 副标题说明自然语言输入、条件整理、关键追问、推荐依据、代价和结论变化条件。
- Hero 不再展示“演示模式”“模型配置已启用”“配置 API”和“服务端决策工作台”。
- 双 Offer 场景成为唯一的旗舰示例。
- 旅行、购物、学习和饮食作为次级示例保留。
- placeholder 改为双 Offer 复杂决策。
- 旗舰和次级示例继续填充输入框，并沿用现有提交流程。
- 桌面与窄屏下主次清晰，无溢出。

## 设计方案

### Hero 价值文案

保留主标题。副标题使用：

> 说出你正在纠结的选择。Choice Agent 会帮你补齐关键条件、整理候选、过滤硬约束、比较取舍，并告诉你为什么推荐、需要接受什么代价，以及什么变化会改变当前结论。

输入标签保留“你最近在纠结什么？”，placeholder 改为：

> 比如：我拿到了两个 Offer，一个稳定但成长慢，一个机会更多但通勤很远，我该怎么选？

删除 Hero 内的模型/演示状态 banner。模型配置继续由顶部“设置”和设置页承载。

### Offer 旗舰示例

在输入框下新增独立的旗舰示例卡：

- 标签：`推荐体验`；
- 标题：`帮我比较两个 Offer`；
- 正文：`A 公司工作稳定、离家近，B 公司成长更快但每天通勤两小时，我应该怎么选？`；
- 点击继续使用 `data-action="general-example"`，填充完整问题并聚焦输入框。

旗舰示例不自动提交，让用户可以先检查和修改文本。

### 次级示例

旅行、购物、学习和饮食放在旗舰示例之后，使用更紧凑的次级按钮。按钮可显示短标题，但 `data-example` 保留完整问题。Offer 不重复出现在次级列表。

### 右侧价值表达

将当前流程卡改为四项用户收益：

1. `不用先整理`：自然描述纠结即可开始；
2. `看清决策条件`：目标、候选、偏好和硬约束可检查、可修改；
3. `先补关键缺口`：必要时只追问会影响结论的信息；
4. `理解推荐边界`：看到依据、代价和可能改变结论的条件。

### Hero 下方内容

收敛与右侧重复的流程卡，改为简洁说明“过程可检查、条件可修改、结论可解释”。保留通用 Demo 入口时使用“查看完整示例”等用户语言，并放在首屏价值内容之后。底部开发者入口保持不变。

## 关键流程

首次访问：`#/` → `renderGeneralHome()` → 差异化文案与输入框 → Offer 旗舰示例 → 次级示例 → 用户收益说明。

点击 Offer：`general-example` → 完整问题填入 textarea → 用户修改 → `submitGeneralDecision()` → `conversation.startGeneral()`。

自由输入：提交逻辑保持不变；空输入继续提示，非空输入继续领域识别并创建决策对话。

## 接口与兼容性评估

- 不改变公开 API、请求体、响应结构或数据库。
- 不改变 `generalDecisionForm`、字段名和 `general-example` 事件协议。
- 原旅行、购物、学习和饮食示例仍保留，只调整层级和文案。
- Offer 继续依赖现有通用领域识别，不新增 `career` 后端领域。
- 当前测试未发现依赖首页 DOM 文案的用例。

## 风险和边界情况

- 副标题较长，需要控制行宽和响应式字号。
- 旗舰卡会增加高度，应通过删除 banner 和重复卡片控制首屏尺寸。
- 次级按钮显示短文案时，完整 `data-example` 不能缩短。
- 首页表达系统支持分析结论变化条件，但不保证首次回复总会给出完整敏感性分析。
- 模型状态移出首页后，配置发现仍由顶部设置入口保障。

## 验证方案

静态与自动验证：

- 复读 `app.js`、`app.css`、Plan Todo 和 CHANGELOG，确认实际落盘。
- 搜索首页是否仍有工程 banner、服务端工作台和饮食 placeholder；确认设置页相关功能仍在。
- 运行 `node --check src/choice_agent/static/assets/js/app.js`。
- 运行 `python -m pytest`。
- 运行 `git diff --check` 并检查最终 diff 只包含计划内文件。

页面行为验证：

- 打开首页检查桌面首屏结构与文案。
- 点击 Offer 旗舰示例，确认完整问题写入并聚焦输入框。
- 修改并提交 Offer 问题，确认进入现有通用决策对话。
- 抽查旅行和饮食示例，确认原分流行为。
- 检查窄屏内容顺序、换行、触控区域和横向溢出。
- 检查设置页仍可访问并显示模型配置。

如浏览器控制不可用，将执行静态检查、服务 HTTP 检查与自动测试，并明确未完成的视觉验收。

## 注意事项与技术折衷

- 本次只调整首页表达和展示层级，不扩大全局导航范围。
- 旗舰示例沿用“填充后由用户提交”，符合可检查、可修改的定位。
- 首页移除运行状态提示，实际结果页继续承担演示数据和来源边界说明。
- 右侧以用户收益回答产品价值，具体步骤由后续对话界面展示。
