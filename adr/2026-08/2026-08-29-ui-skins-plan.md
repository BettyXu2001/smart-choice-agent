# UI 多套皮肤 Plan

## 目标和成功标准

目标：为 `choice-agent-v2` 前端增加多套 UI 皮肤能力，保留当前浅绿色皮肤，并新增一套参考 `eat-what` 的年轻鲜亮皮肤。

成功标准：

- 默认视觉仍是当前浅绿色风格；
- 用户可以在页面上切换到第二套年轻鲜亮皮肤；
- 主题选择刷新后仍保留；
- 主题切换覆盖首页、饮食模式、聊天、餐食管理、Trace 和评估页面的主要视觉元素；
- 不引入新依赖，不改变后端接口；
- 移动端顶栏不出现明显挤压、重叠或不可操作；
- 验证通过项目现有测试，并尽可能完成页面行为验证。

## 架构或逻辑设计

采用静态前端内的轻量主题系统：

1. 在 `app.css` 中保留 `:root` 作为默认浅绿色主题；
2. 新增 `body[data-theme="pop"]` 覆盖 CSS 变量和少量主题专属样式；
3. 在 `app.js` 中增加主题枚举、读取/保存 localStorage、切换函数和事件处理；
4. 在 `index.html` 顶栏中增加主题切换控件；
5. 页面启动时尽早应用保存的主题，减少用户刷新后的主题闪动。

主题定义：

- `mint`：当前浅绿色，作为默认主题；
- `pop`：参考 `eat-what` 的年轻鲜亮主题，主色使用橙色，辅以黑白高对比和更强边框/投影。

## 关键流程

### 首次加载

1. 页面加载；
2. 前端读取 `localStorage.choiceAgentTheme`；
3. 如果值为已知主题，则设置到 `body.dataset.theme`；
4. 未设置或值非法时使用 `mint`；
5. 渲染页面并同步主题按钮选中态。

### 用户切换主题

1. 用户点击主题按钮；
2. JS 校验主题值；
3. 更新 `state.theme`；
4. 写入 localStorage；
5. 更新 `body.dataset.theme`；
6. 同步按钮选中状态；
7. 展示轻量 toast，例如“已切换为活力橙”。

## 每个文件计划修改内容

### index.html

在顶栏右侧用户 ID 附近加入主题切换控件：

- 使用单个皮肤按钮，点击后展开下拉选项；
- 文案使用“清新绿”、“活力橙”；
- 使用 `data-action="set-theme"` 和 `data-theme-value` 供事件代理识别；
- 保留用户 ID 输入，不改变其行为；
- 控件应有 `aria-haspopup`、`aria-expanded` 和选项 `aria-checked`。

增加内联启动脚本：

- 读取 localStorage；
- 对非法值做白名单判断；
- 只设置 `document.body.dataset.theme`，不承担业务逻辑。

### app.css

保留当前 `:root` 变量作为 `mint`：

- 当前颜色尽量不变；
- 如需要，新增变量名称但保持值相同。

新增 `body[data-theme="pop"]`：

- 背景：鲜亮橙色或橙色渐变，但内容区保持白底保证可读；
- 主色：`#FF6321`；
- 强调色：可使用蓝色 `#3B82F6` 或亮黄色作少量辅助；
- 文本：使用接近黑色；
- 边框：比默认主题更深；
- 阴影：更接近 `eat-what` 的硬投影，但控制强度，避免后台页疲劳；
- 按钮和选中态：增加黑底白字或橙黑组合；
- badge、chip、stat-card、message bubble、table header、json box 等主要组件补齐主题适配。

新增主题控件样式：按钮尺寸稳定、下拉层不遮挡主导航、移动端可占满宽度、选中态明显、不遮挡用户 ID。

### app.js

新增常量：

- `THEME_STORAGE_KEY`；
- `THEMES` 或 `THEME_LABELS`。

新增函数：

- `getSavedTheme()`：读取 localStorage 并校验；
- `applyTheme(theme)`：设置 `document.body.dataset.theme` 并同步控件状态；
- `setTheme(theme)`：更新 state、保存、应用、toast。

调整初始化：

- `state` 增加 `theme`；
- `initTheme()` 在首次 `render()` 前执行；
- `handleClick()` 增加 `set-theme` 分支。

错误处理：localStorage 读写可能在极少数浏览器设置下失败，应使用显式降级。读失败返回默认主题；写失败仍切换当前页面并提示“主题已切换，但无法保存偏好”。

## 兼容性和破坏性变更评估

- 不修改后端接口，无 API 破坏性变更。
- 不修改数据模型，无迁移。
- 不新增依赖，无构建变化。
- localStorage 新增一个前端偏好键，对旧用户无影响。
- 默认主题保持当前浅绿色，已有视觉不会被强制改变。

## 风险和边界情况

- 顶栏空间不足：移动端可能挤压导航、用户 ID 和主题控件，需要 CSS 响应式验证。
- 主题覆盖不完整：硬编码颜色可能导致第二套皮肤混入旧绿色，需要检查主要页面。
- 对比度风险：橙色背景上浅色文字可能不清晰，按钮和文字应优先使用黑白高对比。
- 首次加载闪动：如果保存的是第二套主题，CSS 加载后 JS 才设置主题可能短暂显示默认主题；内联小脚本可降低影响。
- 后台页面疲劳：Trace 和评估页不应过度使用高饱和背景，应保留工具页可读性。

## 验证方案

自动验证：

- 运行 `python -m pytest`，确认现有测试不受静态前端变更影响。

静态检查：

- 检查 `git diff`，确认只包含计划内文件。
- 搜索主题相关硬编码绿色，确认第二套主题不会明显漏色。
- 搜索空 `catch`，确认没有新增静默错误。

行为验证：

- 启动本地应用或静态服务；
- 打开首页，确认默认浅绿色；
- 切换到活力橙，确认顶栏、按钮、卡片、badge/chip、聊天气泡、表格等主要组件变化；
- 刷新页面，确认保留活力橙；
- 切回浅绿色并刷新，确认恢复；
- 检查移动端宽度下顶栏、导航、用户 ID 和主题控件不重叠。

## 注意事项与技术折衷

- 第二套皮肤只借鉴 `eat-what` 的视觉语言，不迁移它的 React/Tailwind/motion 实现。
- 暂不做主题编辑器、自定义颜色或更多皮肤，避免扩大范围。
- 暂不引入图标库；如需主题控件图形反馈，用文字和 CSS 状态即可。
- 当前项目是通用决策工具，不应完全变成 `eat-what` 的强娱乐化抽签盘风格。
